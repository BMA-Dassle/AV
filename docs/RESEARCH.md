# Research notes: replacing the Head Pinz Fort Myers TV control page

Collected 2026-09-28. Raw captures live in `research/` (existing page HTML, OpenAPI spec, SHEF PDF and text, live variable dump).

## 1. What the current page is

`http://10.43.60.245/headpinz-fortmeyers/` is an **Allonis myServer** "Smart App" (Kendo UI + custom `ui-*` web components, `fxApp.js`). It is not a hand-written page: the layout is generated by Allonis MyDesigner at a fixed 1366 x 999 design size and scaled.

How it works:

- The page loads scene fragments (`overlay-floorplan.html`, `overlay-mainnavigator.html`, `overlay-video-sources.html`, `overlay-preview.html`, `directv.html`, `guide.html`, `favorites.html`, `presets-popup.html`, `settings.html`).
- Every control carries a `servercmd` string (for example `Activate.Video|[[video_out_18_id]]`, `AV|[[active_device]]~Tune~618`) that is POSTed to `/api/doCommand`. State comes back over a WebSocket as `name^value` pairs that fill `[[variable]]` placeholders.
- The floorplan scene is a 1300 x 1730 scrollable CAD drawing with **45 TV buttons** placed at absolute coordinates. Each button shows only the channel callsign of whatever box feeds it (for example `FS2HD`) and a caption with the TV name.
- Source picking is a separate left-hand scroller of 14 "video sources" (`/api/getavsources/video`): DTV 1-8, Bowling Music 1-2, MMS1, MMS2, Atmosphere, Meeting Room.
- Channel changes happen on a third scene (`directv.html`), a full DirecTV remote acting on "the active device", with no indication of how many TVs that box feeds.
- The guide scene shows "myTV is running in demo mode. Viewing your channel listings requires an active TV Guide subscription." The favorites feed (`/api/tv/guide/favorites/9166`) returns rows with empty titles.

### Why bartenders get confused

1. Three separate mental steps on three screens: pick a TV on a map, pick a box in a list, then change the channel on a remote. Nothing tells you they are linked.
2. The 8 DirecTV boxes are shared by 46 screens. Changing the channel on "DTV 7" silently changes 14 TVs. The old UI never says so.
3. The map shows callsigns (`WBBH`, `FS2HD`), not what is on, and the drawing is too dense for a phone.
4. There is no "find the game" entry point. Staff have to know the channel number.

## 2. Pandora REST API, HDTV endpoints

Base `https://bma-pandora-api.azurewebsites.net/v2`, OpenAPI 3.1, version 2.4.102. Every route needs a **bearer JWT** (`Authorization: Bearer ...`); unauthenticated calls return 401. There is no login endpoint in the spec, so the token is issued out of band. Full schemas are in `research/hdtv-endpoints.txt`.

The AV system is an AV-over-IP matrix: encoder nodes (one per DirecTV box, music player, signage PC) and decoder nodes (one per TV). Pandora relays JSON to the nodes (UDP 6004 or TCP 6006) from Azure.

Endpoints that matter for the first page:

| Endpoint | Use |
|---|---|
| `POST /hdtv/source` | The one-call "put source X on TV Y": opens a full-screen window on the decoder showing `encoder {ip, devid}` and opens its audio. Takes `ip` (one decoder) or `ips` (many). 200 only if every node succeeded, else 502 with per-node results. |
| `POST /hdtv/window/close` | Blank a TV (`all: true`). |
| `POST /hdtv/audio/volume`, `/audio/open`, `/audio/close` | Per-decoder audio. |
| `GET /hdtv/status/{ip}` | What a decoder is showing now (windows with `url`/`devid`, audio state, HDMI input). This is how the app can learn the true floor state without trusting its own memory. |
| `POST /hdtv/scan`, `GET /hdtv/devices/{locationID}` | Discover encoder/decoder nodes through the site's Q-SYS Core. Needs the Square location ID whose `qsysAddress` attribute names the Core. |
| `POST /hdtv/scene/call|save|delete` | Node-side scenes (window layouts), not needed for v1. |

What we still need from BMA/Pandora: a JWT for this app, the Square `locationID` for Fort Myers, and the encoder `devid`/IP per DirecTV box and the decoder IP per TV (a scan gives IPs and user-set names; mapping names to the 46 TV labels is a one-time setup task).

## 3. DirecTV box API (SHEF)

DirecTV receivers expose **SHEF** (Set-top box HTTP Exported Functionality) on port 8080. Spec: DTV-MD-0359 rev 1.3.C, 2011, saved as `research/shef.pdf`. It must be enabled on each box: Menu > Settings > Whole-Home > External Device > Allow.

| Call | Purpose |
|---|---|
| `GET /tv/getTuned?clientAddr=0` | Current channel (`major`, `minor`), `callsign`, `title`, `episodeTitle`, `startTime`, `duration`, `isRecording`. Polled to show "what is on each box". |
| `GET /tv/tune?major=618` | Change channel directly. |
| `GET /remote/processKey?key=chanup&hold=keyPress` | Any remote key: power, guide, exit, up/down/left/right/select, chanup/chandown, prev, 0-9, dash, enter. |
| `GET /tv/getProgInfo?major=&minor=&time=` | Program details for a channel at a time (limited to what the box has cached). |
| `GET /info/getLocations` | On Genie servers (HR34/44/54), lists mini clients and their `clientAddr` (MAC hex, no colons). Pass `clientAddr` on every call to control a specific client. |
| `GET /info/getVersion`, `/info/getOptions`, `/info/mode` | Diagnostics. |

Caveats found in the field:

- Responses are `{ status: { code, commandResult, msg, query }, ...fields }`. A conflict (box busy) returns code 500 with `commandResult: 1`.
- Some 2023+ firmware returns 403 on `getTuned` until External Device Access is re-allowed after an update ([DirecTV community thread](https://forums.directv.com/conversations/satellite-equipment/shef-interface-gettuned-command-no-longer-works/64e90131015a7d5b34648665)).
- The public spec is from 2011 and is the last one DirecTV published. Community references: [whitlockjc/directv-remote-api](https://github.com/whitlockjc/directv-remote-api), [SHEF PDF](https://blog.solidsignal.com/docs/DTV-MD-0359-DIRECTV_SHEF_Command_Set-V1.3.C.pdf).
- The old Allonis controller already drives these boxes (device ids 56-63 with channel/title variables), so the boxes are reachable from the LAN and SHEF is presumably enabled. Their IPs were not visible in the variable dump; get them from the Allonis device list or DHCP.

## 4. TV guide: needs a new API

Nothing in Pandora provides listings, and the old controller's guide subscription is dead. The Guide page needs `GET /api/guide?from=&hours=3&filter=sports` returning channels with programs for the DirecTV Fort Myers lineup. `src/guide.js` defines the provider interface and ships a mock. Real options: Gracenote/TMS (industry standard, paid), Schedules Direct via XMLTV (cheap, JSON, lineup "DIRECTV Fort Myers"), or TVPassport/TV Media. A SHEF `getProgInfo` fallback can fill "what is on this channel now" for a channel the box can see, but not a grid.

## 5. Proposed architecture

```
iPad / phone (bartender)          Node app (on site LAN or Azure)         Hardware
┌────────────────────┐   HTTP/SSE  ┌──────────────────────────┐  HTTPS   ┌─ Pandora /hdtv/* ─ AV nodes (decoders per TV)
│ TVs page           │◄───────────►│ /api/state, /api/events  │─────────►│
│ Guide page         │             │ /api/tvs/source          │  HTTP    ├─ DirecTV boxes 1-8 (SHEF :8080)
└────────────────────┘             │ /api/boxes/:id/tune|key  │─────────►│
                                   │ /api/guide  (new)        │─────────►└─ Guide provider
                                   └──────────────────────────┘
```

The Node app keeps a small model: TV -> source, box -> tuned channel. It refreshes boxes from SHEF every 10 s and can reconcile TVs from `GET /hdtv/status/{ip}` on a slower cadence. It runs fully in `MOCK=1` mode with the live snapshot as seed data.
